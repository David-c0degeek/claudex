# 04.5 — Mechanical test gate outside the lock

Design of record. Written to CX's TURN-231 pins, revised to TURN-232 (3 Blocking + 2 Important + the
phase-graph ruling) and to TURN-233 (1 Blocking + 3 Important). **No code exists yet.**

TURN 232 corrected the TURN-231 lifecycle order; this document follows the corrected one.

## Authority and non-goals

The gate is the sole authority deciding a mechanical test outcome. It owns the attempt lifecycle, the
durable attempt record, and the identity proof of what was tested. It does not own phase edges (the
engine does), run identity (attach), or the review packet (04.3).

The runner returns **facts**, never a verdict. Mapping facts to an outcome is the gate's; the engine
consumes the outcome. A runner bug must not be able to become a verdict.

**Non-goal:** the cancel *lifecycle* (05.7). 04.5 ships the durable per-attempt cancel-REQUEST
primitive and the state shape 05.7 needs — the coherence problem is solved here, not deferred.

## Slice order

1. **`internal/proctree`** — authority-neutral leaf.
2. **The schema step, ATOMIC** — run-policy v2 (D016 amendment) + attempt record/store contract +
   RunState **v8**, one commit. Policy v2 cannot land alone: state embeds the frozen policy and its
   decode calls the current policy validator.
3. **The lifecycle machine** — start / run / finalize / recovery + crash matrix.
4. **Composition** — coordinator/engine/submit/status wiring, the `FixReturn == VERIFY` route change,
   the VERIFY packet entry, and the adversarial route tests.

## 1. `internal/proctree` — containment (TURN-233 pin 1)

`PR_SET_PDEATHSIG` applies to the **direct child only** and is cleared in its forked children, so it
is not transitive. A bare PGID persisted for a later process risks PID reuse. Containment is named per
platform with the executable that provides it and the guarantee it actually gives.

| Platform | Mechanism | Executable | Guarantee |
|---|---|---|---|
| Windows | create **suspended** → assign to a **kill-on-close Job Object** with breakaway denied → resume | none extra | **transitive and non-escapable.** The coordinator holds the only handle; its death closes the handle and the OS kills the job. |
| Linux | direct child is claudex re-executed via `/proc/self/exe` in a **guarded supervisor mode**, which takes `PDEATHSIG`, puts the real command in its own **process group**, and on parent death kills and reaps that group | the **same claudex binary** — no second artifact, so the single-distributable-binary property holds | **ordinary descendants only.** A task-controlled child holds the user's OS authority and may `setsid` out of the group; that descendant is NOT contained. |
| other POSIX | fresh process group, best-effort kill by the live owner | none | **none after owner death.** |

`os/exec` cannot install a Go signal handler between fork and exec, which is why the supervisor must
be a real re-executed process rather than a callback.

**Scope of the guarantee, stated rather than implied.** Only Windows gives a transitive,
non-escapable proof. On Linux the supervisor proves *"no process remains in the group I owned"* — it
cannot prove *"no descendant escaped"*, because a deliberate `setsid` leaves the group unobservably.
So recovery accepts a clean supervisor reap as proof, and **BLOCKS for operator action** whenever the
group was escaped, the supervisor did not reap cleanly, or the platform provides no proof at all. The
gate never asserts a tree is dead on the strength of a mechanism that cannot show it.

**Command-surface consequence, surfaced not hidden.** The supervisor mode is a dispatchable route of
the claudex binary. Concealing it would be precisely the unenumerated-route bug found in the alias
namespace at TURN 224, so it is **added to the enumerated command surface** and the 03.9 exact-set
invariant is amended to include it, with its non-agent-facing nature recorded. It is guarded (refuses
unless invoked with the internal marker and a live parent) but it is *enumerated*.

On timeout/cancel: kill the whole tree, drain pipes, then `wait`/reap **before returning** — a
returned-but-unreaped tree is indistinguishable from a live one.

`cmd.Env` is **non-nil**, built from the frozen policy (§2); `cwd` is the run worktree — a fixed
directory, **not** confinement: the child holds the user's OS authority.

**Tests:** surviving grandchild; timeout; explicit cancel; spawn failure; and **killing the parent
coordinator process itself** — exercising the **actual shipped supervisor path**, not a test-only
helper production cannot launch. On a platform with no proof, the test asserts recovery *blocks*
rather than passing vacuously.

## 2. Run-policy v2 (D016 amendment)

`test_gate` is **exactly one of** `disabled: true` **or** non-empty `argv`. No implicit shell — a
shell must be named (`["sh","-c","…"]`).

```jsonc
"test_gate": {
  "argv": ["go", "test", "./..."],          // XOR "disabled": true
  "env": { "inherit": ["PATH"], "set": {} } // see below
},
"limits": {
  "test_timeout_seconds":     1800,
  "max_test_attempts":        20,      // NEW: ledger ceiling; 0 < n <= config.MaxBudget
  "max_test_output_bytes":    32768,   // NEW: combined RETAINED excerpt, RAW bytes
  "max_test_record_bytes":    65536    // NEW: CANONICAL-byte ceiling of result.v1.json
}
```

**Bounds must be cross-validated, not merely present (TURN-233 pin 3).** The result is issued to the
verifier as an evidence-packet file, so a policy-valid record that cannot be packetized would be a
policy that permits an unissuable run. Validation requires:

`max_test_record_bytes <= evidence_max_file_bytes <= evidence_max_total_bytes`

with defaults chosen to satisfy it (65536 <= 98304 <= 262144). `max_test_attempts` must be positive
and bounded by the shared storage ceiling `config.MaxBudget`, since every entry lands in a
full-snapshot RunState.

**Canonical expansion is bounded by construction.** Retained excerpts are **base64**, so encoding
expands by exactly 4/3 and the worst case is arithmetic rather than a guess — JSON string escaping of
arbitrary control bytes could otherwise expand ~6x and silently exceed the ceiling. The record builder
computes the excerpt budget from the CANONICAL ceiling backwards (record ceiling, minus a fixed
metadata allowance, times 3/4) and **deterministically shrinks the excerpt** to fit. It never emits a
record it cannot encode, and never accepts output it cannot bound.

- `argv[0]` nonblank; NUL rejected anywhere; intentionally **empty later arguments preserved**;
  secrets rejected in every executable/control element.
- **Environment is frozen at attach, not read per attempt (pin 2).** Naming an ambient variable makes
  the inheritance intentional but does not freeze its VALUE — `PATH` can change between bootstrap and
  an attempt, and identity binding would only detect the drift *after* it had already changed
  execution. The allowlisted values are therefore **resolved once at first attach into the frozen
  `EffectivePolicy`**, exactly like every other run input, and attempts read the frozen values.
- **`HOME` is NOT inherited by default.** Common tools auto-load credential-bearing Git/npm/cloud
  config from it, which would have contradicted this same contract's "no provider token". The default
  allowlist is the minimal execution set only — `PATH`, plus `SystemRoot`/`ComSpec` on Windows — and
  the run supplies a **tool-owned per-run scratch `HOME`/cache/temp** pointing inside the run
  directory. Anything more must be named explicitly by the operator.
- **Secrets are REJECTED, not redacted, in the environment.** Every resolved inherited value and every
  `env.set` value is secret-checked before it is persisted or executed. Rejection (rather than
  redaction) is what lets the frozen environment be bound by a digest over its ACTUAL values: a digest
  over redacted pairs could not prove equality, since distinct secrets collapse to the same marker.
  If secret-bearing inheritance is ever wanted, it needs a different authority and a decision row.
- `RunPolicyVersion` → 2. A v1 document is **refused**, never reinterpreted.
- **Parse-order fix:** `ParseRunPolicy` today probes only for the *presence* of `schema_version` then
  `strictDecode`s the v2 shape before comparing versions (`internal/config/config.go:229-253`), so a
  v1 policy carrying `command` fails with an unknown-field error instead of version remediation. The
  probed version must be compared **before** the strict decode.

## 3. On-disk shapes

Per-run attempt root `<run>/tests/<attempt_id>/`:

| Leaf | Written | Meaning |
|---|---|---|
| `intent.v1.json` | before the active CAS | immutable: attempt id, argv, cwd, **effective env identity**, frozen policy bounds, tested commit/tree, start revision |
| `result.v1.json` | **inside the final guarded section**, after the final identity observation | the one immutable canonical record; the digest state binds |
| `stdout`, `stderr` | during the run | bounded, **redacted** retained excerpts |
| `cancel.requested` | any time | durable, idempotent, rooted, no-clobber, durability-confirmed |
| `lease` | held while running | OS-held; held ⇒ live owner, unheld ⇒ owner died |

**Effective environment identity.** Intent and result bind the sorted variable **names** plus a
digest over the canonical redacted `name=value` list — so an environment change is detectable without
persisting a secret.

**Streams — representation pinned for arbitrary bytes (TURN-233 pin 4).** Process output is
arbitrary bytes; the harvested vectors explicitly include non-UTF-8 raw streams.

- The `stdout`/`stderr` leaves are **non-authoritative crash-time staging**: partial evidence retained
  for an interrupted attempt, never the thing state binds.
- The **immutable result embeds the exact retained representation** as **base64**, so the record is
  self-contained, lossless for invalid UTF-8, and the verifier recomputes every fact from the record
  alone rather than trusting a sibling leaf.
- It binds, separately and unambiguously: `stdout_bytes`/`stderr_bytes` (raw byte counts BEFORE
  encoding) and `stdout_sha256`/`stderr_sha256` over the **entire redacted stream**, computed
  streaming; plus `stdout_retained_b64`/`stderr_retained_b64`, their raw retained byte counts, and
  `truncated` flags for the bounded excerpt actually kept, under a deterministic **head+tail with an
  explicit elision marker** rule within `max_test_output_bytes`.

**No raw secret-bearing bytes reach disk.** Redaction happens in the streaming path *before* any
write, including to the staging leaves.

**The chunk-boundary guarantee needs a bounded streaming redactor**, not the current whole-string
`redact.Text`/`redact.Bytes` applied independently per chunk — that would miss any secret straddling a
read boundary. The redactor carries an overlap window of at least the longest matchable token and is
its own tested unit, since correctness here is what keeps the "no secret on disk" claim true.

## 4. RunState v8 (TURN-231 pin 1, TURN-232 pin 2)

A store alone is insufficient: `SubmitTestOutcome` is non-idempotent and delegates replay identity to
a future journal, and `engine.Apply` records no TESTS source (`internal/engine/engine.go:612-620`), so
RunState has no attempt identity at all.

- `ActiveTestAttempt *TestAttemptRef` — at most one. Binds attempt id, start revision, tested
  commit/tree, intent digest, and a **`CancelPending bool`**.
- `TestAttempts []FinalizedAttempt` — **append-only**; binds attempt id, start/bound revision, tested
  commit/tree, canonical result digest, execution + identity outcome, terminal reason, and resulting
  revision.

**Invariants.**
- At most one active ref.
- The ref may exist at **ownerless TESTS**, *or* in a **cancelled lifecycle awaiting terminal
  binding** (`CancelPending`). This is what lets 05.7 mark `LifecycleCancelled` immediately so
  `status`/`wait` wake, without discarding the only identity the runner can finalize. The previous
  "non-TESTS has no active ref" rule would have rejected that state.
- State references an intent or result **only after** the canonical record is durably published and
  re-confirmed.
- A result digest already in the ledger cannot authorize a second, differing outcome.
- `len(TestAttempts) <= max_test_attempts`.

**Two finalization shapes (pin 2).**
- **Outcome finalization** — `pass`/`fail`: atomically moves the exact active ref into the ledger
  **and** applies the TESTS edge, in one CAS.
- **Ledger-only finalization** — `cancelled` / indeterminate: atomically clears the active ref and
  appends the ledger entry, applies **no** edge, leaves the test budget untouched, and leaves the run
  explicitly retryable (ownerless TESTS) or cancelled.

**Cancel vs result race.** Both CAS under the run guard, so one is first. If cancel binds first the
attempt becomes `CancelPending` and the runner's subsequent finalization is a **ledger-only
`cancelled`** binding — the result is still bound as evidence, never discarded. If the result binds
first, the cancel is a no-op against a finalized attempt.

**Attempt exhaustion (pin 5d).** Indeterminate retries are deliberately **not** limited by
`TestFixes` — the code did not fail. Without a ceiling they would grow a full-snapshot RunState
without bound, so `max_test_attempts` halts the run for operator action with a typed
`ErrTestAttemptsExhausted`. Repeated indeterminacy means the environment is broken; classifying it as
a code test failure would be a lie that also burns the fix budget.

## 5. The lifecycle machine (TURN-232 pin 1 — corrected order)

1. **Under the run guard:** authorize exact ownerless TESTS **and no active attempt**; freeze the
   latest accepted commit/tree and the policy; prove exact identity (registered run branch / HEAD /
   commit / tree / index / worktree); mint and lock one attempt.
2. Durably publish the immutable **intent**.
3. **CAS-bind** `ActiveTestAttempt`.
4. **Release the run guard.**
5. Execute while holding the per-attempt **OS lease**. The subprocess is entirely outside the lock.
6. **Reacquire the run guard.**
7. Re-authorize the exact active attempt; perform the **final exact identity observation**.
8. Construct and durably publish the **one canonical result** — it can now truthfully freeze
   `unchanged` vs `changed`, which it could not before step 7.
9. **CAS the outcome into state**, then release the guard.

Publishing the result *before* the final locked observation (the TURN-231 order) was wrong: the record
is immutable and contains the identity distinction, so it cannot be written before the fact it
asserts exists. Only bounded record publication is inside the lock; the subprocess never is. This also
**serializes a late operator-cancel against outcome finalization**.

**Concurrency.** Active + **held** lease ⇒ report the same running attempt, never start another.
Active + **unheld** lease ⇒ the owner died.

**Orphan policy (no rerun).** A possibly side-effecting command is never re-run automatically. The
orphan terminalizes `interrupted` with partial evidence retained, requires an explicit **new**
attempt, and does not consume the test-fix budget. Recovery must **prove no old process tree remains**
(§1) before permitting another attempt; where the platform cannot prove it, recovery blocks.

## 6. Trigger and cancel

**No new agent-facing verb.** The `submit` orchestration that durably enters TESTS starts or resumes
the gate **after releasing the acceptance guard**; accept-once replay/recovery covers a crash in the
enter-TESTS → bind-active gap. The active ref keeps `status` lock-free and coherent and lets a second
invocation report *already running*.

`cancel.requested` is durable, idempotent, rooted, no-clobber and durability-confirmed; the runner
polls it **outside** the run lock. Operator cancel terminalizes `cancelled` and **never routes
TESTS→FIX** — nobody's code failed. A **caller context disappearing** is not an operator decision: it
is `interrupted`/indeterminate under the orphan policy, retryable, budget untouched.

## 7. Outcome mapping (TURN-232 pin 5e) — separate execution and identity

Overlapping facts are removed by construction rather than by a precedence list: the record carries two
independent fields, and the outcome is a total function of the pair.

`execution` ∈ `ok | nonzero | timeout | cancelled | spawn_failed | interrupted`
`identity` ∈ `unchanged | changed | unobserved`

| execution | identity | outcome |
|---|---|---|
| `cancelled` | any | **cancelled** — ledger-only, no edge, no budget |
| `spawn_failed`, `interrupted` | any | **indeterminate** — retryable, no budget |
| any | `unobserved` | **indeterminate** — the gate cannot decide what it cannot observe |
| any | `changed` | **fail** |
| `timeout` (`exit_code: null`) | `unchanged` | **fail** — ordinary test-failure edge |
| `nonzero` | `unchanged` | **fail** — ordinary test-failure edge |
| `ok` (exit 0) | `unchanged` | **pass** |

Cancel outranks timeout: operator intent supersedes a bound. `disabled: true` produces a durable
no-process result (`execution: ok`, `terminal_reason: "disabled"`) with the **same exact commit/tree
proof**, and is admissible **only when the task declares no required tests**.

## 8. The tested-tree obligation and the phase-graph ruling

Identity is proven at attempt **start** and again at **final observation** (step 7), the successful
observation being the external-filesystem linearization point. The passed attempt's commit/tree is
retained in the ledger and **re-proven on the verifier submit, immediately before VERIFY→DONE** —
proving it only when tests finish still lets a clean `reset --hard` land afterwards.

**The non-adversarial hole.** A VERIFY failure routes its FIX back **directly to ownerless VERIFY**
(`internal/engine/engine.go:433-456`), so that fix produces a new accepted commit *after* the last
passed attempt and no tests rerun. Two agents behaving correctly reach it.

**Ruling (CX TURN 232), adopted:** in `evalFixImplemented`, `FixReturn == VERIFY` routes to **TESTS
via the existing `RouteToTests`**. No new edge and no gate-only special case — the edge predicate
already admits `FIX → TESTS` (`engine.go:1038-1040`), and every TESTS pass already enters ownerless
VERIFY with a freshly computed pair-generation threshold. That yields VERIFY-fix → TESTS → VERIFY with
**one** edge table. Engine, materialization, and E2E tests update accordingly.

**Verifier evidence (TURN-232 pin 4).** The VERIFY packet currently carries task, agreed plan and
cumulative changed files only (`internal/reviewpacket/phases.go:112-123,221-242`). A ledger entry
makes the pass auditable *internally*, but the fresh verifier must be able to inspect **which argv
ran**, the exit/timeout facts, truncation and output digests. So the VERIFY packet gains the exact
canonical passed `result.v1.json` at a reserved context path, re-verified from the store by attempt
id + digest, counted against packet bounds. Disabled results appear too. **Removing that resolver
entry must fail a mutation test.**

## 9. Crash / TOCTOU table (corrected order)

| Cut | Durable residue | Recovery |
|---|---|---|
| before intent published | nothing | fresh attempt |
| after intent, before active CAS | orphan intent, no state ref | orphan ignored; fresh attempt |
| after active CAS, before spawn | active ref, unheld lease | prove no tree remains → ledger-only `interrupted`; explicit retry |
| after spawn, before process exit | active ref, unheld lease, possibly live tree | prove no tree remains (§1; else block) → ledger-only `interrupted`, partial streams retained |
| after exit, before the guard is reacquired | active ref, streams, **no result** | ledger-only `interrupted` — the identity fact was never observed, so no outcome can be claimed |
| after final observation, before result published | active ref, no result | as above: `interrupted` |
| after result published, before outcome CAS | active ref + durable result | finalize the SAME attempt from the durable result |
| outcome visible, durability unconfirmed | outcome present | re-confirm; never double-apply |

TOCTOU: identity is proven at start and again under the guard at finalization. Between them the guard
is released and an external writer can act — which is exactly why finalization re-proves rather than
trusting the start observation, and why `changed` is a first-class identity outcome.

## 10. Tests the slices must carry

Containment matrix incl. parent-kill **through the shipped supervisor path**, and the escaped-group
case asserting recovery BLOCKS; the bounded streaming redactor across chunk boundaries; base64
round-trip of non-UTF-8 output and deterministic excerpt shrinking against the canonical ceiling;
policy bound cross-validation (`max_test_record_bytes <= evidence_max_file_bytes`) and a positive,
`MaxBudget`-bounded `max_test_attempts`; frozen-at-attach environment with `HOME` absent by default
and secret-bearing values REJECTED; policy v2 XOR/argv/NUL/empty-arg/secret cases and the v1
version-remediation path; stream digest-vs-retention distinction; env identity binding; every cell of
the outcome matrix; each crash cut; cancel-vs-result CAS race in both orders; attempt exhaustion;
`FixReturn == VERIFY` → TESTS → VERIFY end to end; wrong clean HEAD before start, during the run, and
after a passed finalization but before the verifier submit; a VERIFY→FIX commit cannot reach DONE
without a newer passed attempt for that exact commit/tree; and the VERIFY-packet mutation test.
