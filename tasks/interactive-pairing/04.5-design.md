# 04.5 — Mechanical test gate outside the lock

Design of record, written to CX's TURN-231 pins (4 Blocking + 3 Important) on top of the TURN-175
ruling in the 04.5 box. **No code exists yet.** This document is the thing under review; it is
resubmitted before implementation.

## Authority and non-goals

The gate is the sole authority that decides a mechanical test outcome. It owns the attempt lifecycle,
the durable attempt record, and the identity proof of what was tested. It does **not** own phase
edges (the engine does), run identity (attach does), or the review packet (04.3 does).

The runner returns **facts**, never a verdict: exit code (nullable), terminal reason, streams and
truncation metadata. Mapping facts to a pass/fail edge is the gate's, and the engine consumes the
resulting outcome. Keeping those separate is what stops a runner bug from silently becoming a
verdict.

**Non-goal:** the human-gate/cancel *lifecycle* (05.7). 04.5 ships the durable per-attempt
cancel-REQUEST primitive that 05.7 later composes with `LifecycleCancelled`.

## Slice order (pin 5)

1. **`internal/proctree`** — authority-neutral leaf, no claudex types. Own kill/timeout/cancel matrix
   on both platforms.
2. **The schema step, landed ATOMICALLY** — run-policy v2 (D016 amendment) + the attempt record/store
   contract + RunState **v8** bindings and invariants, in one commit. Policy v2 cannot land alone:
   run state embeds the frozen policy and its decode calls the current policy validator, so a v2-only
   commit breaks every existing generation's decode.
3. **The lifecycle machine** — start / run / finalize / recovery, with the crash matrix.
4. **Composition** — coordinator/engine/submit/status wiring, the tested-tree route obligation, and
   the adversarial route tests.

## 1. `internal/proctree` (pin 6)

Build-tagged, returns facts, contains its children by construction rather than by best-effort kill.

- **Windows:** create **suspended** → assign to a **kill-on-close Job Object** → resume. Assigning
  before the process can run is what makes containment total; a job created after resume races the
  child's own spawns.
- **POSIX:** fresh **process group**; on Linux additionally set **parent-death** containment, so a
  coordinator crash cannot leave descendants mutating the worktree after recovery has started.
- On timeout or cancel: kill the **whole tree**, drain pipes, then `wait`/reap before returning. A
  returned-but-unreaped tree is exactly the state recovery cannot distinguish from a live one.
- `cmd.Env` is **non-nil** and built from a documented minimal platform allowlist plus explicit
  policy; nothing is inherited implicitly, so no token, provider credential, or `GIT_*` override
  leaks into a task-controlled process. `cwd` is the run worktree — a fixed directory, **not**
  confinement: the child holds the user's OS authority and this is stated, not implied.

**Tests:** a grandchild outlives nothing; timeout; explicit cancel; spawn failure; and killing the
**parent coordinator process itself** — descendants must die.

## 2. Run-policy v2 (pins 5, 7)

`TestGate` becomes **exactly one of** `disabled: true` **or** a non-empty `argv` array. No implicit
shell: a shell must be named in argv (`["sh","-c","..."]`), so nothing is re-parsed by a platform
shell the operator did not choose.

- `argv[0]` nonblank; NUL bytes rejected anywhere; intentionally empty **later** arguments preserved
  (an empty string is a legitimate argument and must not be dropped).
- Secrets rejected in every executable/control element, as elsewhere.
- `RunPolicyVersion` → 2, D016 amended. A v1 document is **refused**, never reinterpreted.

**Parse-order fix (pin 5):** `ParseRunPolicy` currently probes only for the PRESENCE of
`schema_version` and then `strictDecode`s the v2 shape before comparing versions
(`internal/config/config.go:229-253`), so a v1 policy carrying `command` fails with an
unknown-field error instead of the promised version remediation. The probed version must be compared
**before** the strict decode.

## 3. On-disk shapes

Per-run attempt root `<run>/tests/<attempt_id>/` (bulky payloads stay out of state generations, which
are full snapshots):

| Leaf | Written | Meaning |
|---|---|---|
| `intent.v1.json` | before the active CAS | immutable: attempt id, argv, worktree-relative cwd, frozen policy bounds, **tested commit/tree**, start revision |
| `result.v1.json` | before the outcome CAS | immutable canonical record; the digest state binds |
| `stdout`, `stderr` | during run | bounded, **redacted** retained streams |
| `cancel.requested` | any time | durable, idempotent, rooted, no-clobber, durability-confirmed |
| `lease` | held while running | OS-held; presence+held ⇒ a live owner, presence+unheld ⇒ owner died |

`result.v1.json` binds: attempt id, argv, cwd, tested commit/tree, exit code (**nullable**), terminal
reason, byte counts, truncation flags, and the **stdout/stderr digests over the full REDACTED
streams** — redaction is applied chunk-boundary-safely so a secret split across a read boundary is
still caught, and the digest covers what is actually retained, not a pre-redaction ghost. A frozen
combined retention quota and a maximum canonical-record size are policy bounds, recomputed by the
verifier.

## 4. RunState v8 (pin 1 — Blocking)

A store alone is not sufficient: `SubmitTestOutcome` is explicitly non-idempotent and delegates replay
identity to a future journal, and `engine.Apply` currently discards the TESTS source on both
PASS→VERIFY and FAIL→FIX, so RunState has **no attempt identity at all**. Two additions:

- `ActiveTestAttempt *TestAttemptRef` — at most one; binds attempt id, start revision, tested
  commit/tree, and the intent digest.
- An **append-only finalized-attempt ledger** entry binding attempt id, start/bound revision, tested
  commit/tree, canonical result digest, terminal outcome/reason, and resulting revision.

**Invariants.**
- At most one active attempt; a run at any phase other than ownerless TESTS has none.
- The final state CAS **atomically** moves the exact active ref into the ledger while applying the
  test outcome — never two steps, so no generation shows an outcome without its attempt or vice versa.
- State references an intent or result **only after** the exact canonical record is durably published
  and re-confirmed.
- The same result digest can authorize exactly one outcome; a digest already in the ledger cannot
  authorize a second, differing one.

**Composition (pin 1):** production derives pass/fail **from the validated terminal record**. The
exported `Run.SubmitTestOutcome(pass, digest, …)` must stop being a parallel caller-asserted
production authority — otherwise two authorities can disagree about the same attempt.

## 5. The lifecycle machine (pin 2 — Blocking)

Pinned order:

1. **Under the run guard:** authorize exact ownerless TESTS **and no active attempt**; freeze the
   latest accepted commit/tree and the policy; mint and lock one attempt.
2. Durably publish the immutable **intent**.
3. **CAS-bind** `ActiveTestAttempt`.
4. **Release the run guard.**
5. Execute while holding the per-attempt **OS lease**.
6. Durably publish one immutable canonical **result**.
7. **Reacquire the run guard.**
8. Re-authorize the exact active id, start revision, and result; **finalize once**.

Intent-before-state and result-before-state make every pre-bind artifact a harmless orphan and
guarantee state never references missing evidence.

**Concurrency.** A second invoker seeing active + **held** lease reports the same running attempt and
never starts another. Active + **unheld** lease means the owner died.

**Orphan policy (ruled: no rerun).** A possibly side-effecting command is **never** re-run
automatically. The orphan terminalizes as `interrupted`/indeterminate with its partial evidence
retained, requires an explicit retry as a **new** attempt, and does **not** consume the test-fix
budget — it was not a test failure. Recovery must prove **no old process tree remains** before
permitting another attempt.

## 6. Trigger and cancel (pin 4 — Blocking)

**No new agent-facing verb.** The `submit` orchestration that durably enters TESTS starts or resumes
the gate **after releasing the acceptance guard**. A crash in the enter-TESTS → bind-active gap is
handled by accept-once replay/recovery. State's active ref keeps `status` lock-free and coherent and
lets a second invocation report *already running* rather than starting a rival attempt.

**Cancel.** 04.5 ships the durable, idempotent per-attempt `cancel.requested` primitive (rooted,
no-clobber, durability-confirmed) which the runner polls **outside** the run lock. An operator
cancellation terminalizes as `cancelled` and **must not route TESTS→FIX** — nobody's code failed.
That is distinct from **the caller's context disappearing**, which is not an operator decision: the
attempt is terminalized `interrupted`/indeterminate under the orphan policy above, retryable, budget
untouched. 05.7 later composes `LifecycleCancelled` with this request.

## 7. Outcome mapping (pin 7) — closed table

| Facts | Terminal reason | Outcome |
|---|---|---|
| exit 0 **and** exact unchanged identity | `ok` | **pass** |
| exit nonzero | `exit` | **fail** (ordinary test-failure edge) |
| timeout (`exit_code: null`) | `timeout` | **fail** (ordinary test-failure edge) |
| tree changed during the run | `tree_changed` | **fail** |
| operator cancel | `cancelled` | **no edge**; no FIX, no budget |
| interrupted / spawn failure / identity-observation failure | `interrupted`, `spawn_failed`, `unobserved` | **indeterminate, retryable**; not a test-budget failure |
| `disabled: true` | `disabled` | **pass**, with a durable no-process result and the same exact commit/tree proof |

`disabled: true` is admissible **only when the task declares no required tests** — otherwise a run
could satisfy a required-test contract by turning the gate off.

## 8. The tested-tree obligation (pin 3 — Blocking)

Prove exact registered run branch / HEAD / commit / tree / index / worktree identity at **attempt
start** and again at **result finalization**, with the successful observation as the external-
filesystem linearization point.

Then retain the passed attempt's commit/tree in the state ledger and **re-prove that exact tuple on
the verifier submit, immediately before VERIFY→DONE**. Proving it only when tests finish still lets a
clean `reset --hard` land afterwards.

**The non-adversarial hole this exposes.** A VERIFY failure currently routes FIX back **directly to
ownerless VERIFY** (`internal/engine/engine.go:433-456`, `RouteToVerify`), so a VERIFY-fix produces a
new accepted commit *after* the last passed attempt and **no tests rerun**. This is reachable on the
ordinary path, not by an attacker. Every accepted VERIFY-fix commit must pass through TESTS again
before VERIFY/DONE (or an equivalent single authority must cover it). A strong DONE check **alone**
would not fix this — it would deadlock a legitimate path.

**Regressions:** wrong clean HEAD before start; during the run; after a passed finalization but
before the verifier submit; and a VERIFY→FIX commit cannot reach DONE without a newer passed attempt
for that exact commit/tree.

## 9. Crash / TOCTOU table (pin 2)

| Cut | Durable residue | Recovery |
|---|---|---|
| before intent published | nothing | fresh attempt |
| after intent, before active CAS | orphan intent, no state ref | orphan ignored; fresh attempt |
| after active CAS, before spawn | active ref, unheld lease | terminalize `interrupted`; explicit retry |
| after spawn, before process exit | active ref, unheld lease, live/dead tree | prove no tree remains, then terminalize `interrupted` |
| after exit, before result published | active ref, partial streams | terminalize `interrupted` with partial evidence retained |
| after result published, before outcome CAS | active ref + durable result | finalize the SAME attempt from the durable result |
| outcome visible, durability unconfirmed | outcome present | re-confirm; never double-apply |

TOCTOU: identity is proven at start **and** finalization; between them the run guard is released, so
an external writer can act — that residue is inherent and is why finalization re-proves rather than
trusting the start observation.
