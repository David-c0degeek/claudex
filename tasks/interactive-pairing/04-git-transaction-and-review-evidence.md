# 04 — Git Transaction And Review Evidence

## Goal
Coordinator-owned git as the concrete participant in the 01 prepared-transaction
machine. On an implementation `submit`, build the exact worktree snapshot in a
temporary index, create a commit from that tree, CAS-update the run branch from
the expected old HEAD, **synchronize the checked-out index to the new tree**,
and record the committed object as immutable review evidence. Reviews read a
hashed evidence packet materialized from the committed Git object — never the
live worktree. The mechanical test gate runs as a separate coordinator-owned
subprocess **outside the mutation lock**.

    - **Why not the original wording.** "Block the next lead `submit`" is not implementable: at the lead's submit, raced dirt and the lead's own legitimate work are indistinguishable in the worktree. Detecting there would require persisting the worktree at issuance — a new state-version field plus a coherence invariant every issuance and recovery writer must maintain, i.e. exactly the cost CX rejected for `AssignmentEvidence.Source` at TURN 220. The box's primary sentence was replaced accordingly.
    - **The rule.** Pre-existing dirt observed at a phase BOUNDARY refuses that boundary; nothing is bound — no state revision, no ledger entry, no identity. The successful observation is the LINEARIZATION POINT: dirt present at that instant predates the boundary, and dirt appearing after it belongs to the interval the transition opens. A boundary need not open an EDITABLE interval — a PASS advances into ownerless VERIFY and a budget-exhausted FAIL opens a human gate — so the rule, the sentinel, and every comment are stated BOUNDARY-NEUTRALLY: post-snapshot dirt was detected, this boundary cannot advance.

    - **Scope: DIRT ONLY.** `gitx.WorktreeClean` runs `git status --porcelain`, which proves "clean relative to the CURRENT HEAD" — a pristine checkout of the wrong commit is clean to it — and is NOT authority for "matches the last accepted commit".
