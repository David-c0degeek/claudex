# Lessons — InteractivePairing (run notes)

> Append the moment a slice teaches something; do not wait for the gate.
> Durable lessons migrate to the permanent `tasks/lessons.md` at §7.

- (seed, from the design exchange) The product's own coordination pattern was
  proved live before the plan existed: a role-addressed file mailbox
  (`to-codex.md`/`to-claude.md`) with a `TURN:` sequence and a bounded
  blocking-poll loop is enough for two interactive agent TUIs to converge by
  agreement. The plan productizes exactly this.
- (seed) Git ref update and coordinator state CAS cannot be committed
  atomically; a two-store operation needs a prepared-transaction journal +
  startup reconciliation, not an assumption of atomicity.
- (seed) Interactive attach cannot honestly observe a user's TUI usage; only
  turn/fix counts, artifact bytes, and wall time are enforceable without a
  managed launch + real telemetry channel. Never label a capability "enforced"
  without the mechanism that backs it.
- (design close, 2026-07-16) CX's top-3 Go implementation watch-items (both agents AGREE): (1) **Canonical protocol bytes** — one embedded schema source, exact version negotiation, `json.Decoder.UseNumber()`/number semantics, digest stable across whitespace/key-order/platforms; (2) **Crash consistency** — same-directory atomic writes + fsync durability, the git ref/index/state/receipt journal cut-points, idempotent recovery with read-only commands never mutating; (3) **Real OS behaviour** — process-death locks + race-free process-tree ownership tested on native Windows AND Linux; keep inherited-stdio launch separate from the optional PTY telemetry path.
- (01 close, 2026-07-16) **Audit shipped code against every box before claiming a subject done.** txn's AGREE closed only two of ten boxes; a green build on the packages that happened to exist was not evidence the ledger-projection and legacy-migration boxes were done — they were entirely unbuilt. Enumerate the boxes and map each to code+test before ticking the subject.
- (01 close, 2026-07-16) **A durable guard must key on the real storage boundary, not on decoding a file the real path never reads.** The attach loader reads immutable-generation directories, never `<run>/state.json`; proving the strict decoder rejects a legacy `state.json` tested a path bootstrap never takes. The correct fail-closed guard (`legacy.CheckRunDir`) refuses on the *presence* of any unrecognized `state.json` (legacy → typed refusal; anything else → fail closed), because an empty attach store is not evidence the directory is safe to allocate.
- (01 close, 2026-07-16) **Keep comments plan-agnostic from the first commit.** Decision/box IDs (`D0xx`, `NN.M`) accumulated across subjects 00–01 and had to be swept at close (gate §6.11). Rationale belongs in the code as prose and in the ADR by number — not as a cross-reference from shipped source, which rots when the disposable plan is removed.
- (02.6, 2026-07-16) **On Windows, `os.Rename` is not atomic and `FlushFileBuffers` needs a writable handle.** For immutable artifacts, no-clobber hard-link publication (`os.Root.Link`, fails if the target exists) is race-free with zero reader-side sharing retries — two racers can't overwrite and a reader sees complete-or-nothing. A re-confirm of an already-visible file must open `O_RDWR` (a read-only `Sync` returns "Access is denied"), and any non-absent failure there is a *committed* `PostCommitSyncError`, never a raw error.
- (02.6, 2026-07-16) **A required-field schema change is an on-disk schema-version bump.** Adding the authoritative accepted `Phase` made v1 generations incompatible. Gate the version on a *loose* probe that reads only `schema_version` BEFORE strict decoding, so an older generation fails with clear version remediation instead of a vague unknown/missing-field corruption error.
- (02.6, 2026-07-16) **Reject every non-regular file type by `Lstat` before opening a confined read.** Opening a device/FIFO can block or have side effects even inside an `os.Root`; decide the type first (`!Mode().IsRegular()`), then open with `O_NOFOLLOW|O_NONBLOCK` and re-`Stat` post-open to close the race. `os.Root` will *follow* an in-root symlink, so a symlink must be refused explicitly (it is not confinement-unsafe, but it is not the canonical file the reader was asked for).
- (02.6, 2026-07-16) **Persist one authoritative fact, derive the rest.** Recording role + phase + message_type per accepted turn let a mutator persist three facts that could disagree (and inject via the mirror). Persisting only the coordinator-known `Phase` and deriving role/artifact-type from the single `TurnSpec(phase)` removed the disagreement surface entirely; acceptance is then bound to the exact live, current-revision assigned turn on both the state and submit sides.
- (02.6, 2026-07-16) **Adversarial review converges by removing surface, not adding checks.** Five rounds (TURN 64→68) repeatedly replaced "validate the redundant thing" with "make the redundant thing unrepresentable" (drop role/message_type; single durability primitive; order the stable refusal first). The durable win each round was a smaller boundary, not a longer checklist.
- (00.3, 2026-07-16) `main` is the lean v2 baseline: `claudex/` = agents,
  artifacts, cli, config, gitops, phases, prompts, schemas, state (+templates).
  It compiles (`python -m compileall claudex` OK) but has **zero tests**
  (`tests/` holds only fixtures). The reliability/observability engine — 12
  modules (budgets, evidence, lifecycle, limits, processes, providers, security,
  terminal, recovery, events, provider_events, planops) and all 10 test modules + 6 fixtures,
  +9.3k lines — exists **only on `reliability-observability-refactor`**, not on
  our base. Any Integration-analysis reference to those modules means "port from
  refactor-branch history," not "already present." §2 test baseline: the suite
  is built fresh (or selectively ported); `unittest discover -s tests` currently
  finds nothing.
- (03.9/04.3, 2026-07-26) **A test that confirms what you just built is not a test that catches you being wrong.** Across 04.3 the peer reviewer caught the same defect five times, always in an assertion CC had written and — four of those five times — had described in the review turn as stronger than it was. The instances: the git-accept exactness table passed vacuously because its fixture froze no packet, so the axis under test was never exercised; the agreed-plan assertion checked that the manifest PATH existed and never read the CONTENT, so it sailed over a packet carrying the wrong bytes for two rounds; the pull tests checked that the projected ref equalled state and that a file existed, so deleting the `VerifyRef` call would have left every one of them green; `TestExactCommandSurface` built its "actual" set by iterating the EXPECTED list, so it could only detect a missing verb and never an extra one; and, one level up, that same test closed the `commands` map while `aliases` — resolved FIRST by `run()` — remained an unenumerated second route namespace, so `aliases["run"]="help"` would have routed the forbidden entrypoint past every check. Two framings, both worth carrying: **presence is not correctness** (asserting a thing EXISTS, a path is non-empty, a call returns nil), and **the boundary you asserted may not be the whole boundary** (you closed the set you were looking at, not everything that can reach the behaviour). The practical rule that actually worked: **mutation-test the guard.** Break the thing the test supposedly protects — comment out the verification call, add the forbidden entry — and watch the test fail. It cost about a minute each time, it converted "I believe this is covered" into evidence, and in both cases it was the reviewer, not the author, who first asked whether the assertion could fail at all.
- (02/03.9, 2026-07-26) **A close-out must state what is NOT wired as loudly as what is.** Subject 02 closed `CLOSE` with a recorded Hindsight while the verbs its boxes named (`submit --file`, `wait --timeout N`, `status`) existed only as library functions with zero non-test callers — the binary dispatched `version`/`help`/`inspect-legacy` and `.claudex/mailbox.md` was never written on a shipped path (findings.md M9). Subject 03's slice-h Hindsight disclosed exactly that class for its own leaves; 02's did not, so the §7 gate item "new public surface wired to a non-test caller, **or disclosed** library-only" was ticked on the strength of the first half while the second was what actually applied. The failure was invisible for two subjects because "built and tested" reads like done, and the box wording promised something else — reachable by a user. Rule: at close-out, enumerate the new public surface and name each entry wired or unwired; an unwired entry is fine, an *undisclosed* one silently converts a gate item into a false tick.
- (04.5, 2026-07-26) **A rule that is true of a value is not yet true of the moment the value is used.** Subject 04.5 hit the same shape three times, each time immediately after the preceding one had been "finished". `Terminal.validate` was made complete over every way a terminal can contradict *itself* — and `SendTerminal` then accepted a well-formed `{CommandStarted: true, ...}` before `GO`, an authoritative claim that a launch happened which `GO` alone authorizes. That was fixed with a launch-phase cross-product; one round later `TerminalFrom` was written checking `Leader.Observed` and not `GroupEmpty`, so a clean exit could be reported while descendants were still running in the owned group. The same gap had already appeared between the cleanup receipt and the terminal, which recovery and the coordinator read separately and which nothing required to agree. The generalisation: **value invariants and context invariants are different obligations, and completing one reads exactly like completing both.** The tell is the feeling of having just finished — "I enumerated every contradictory field combination" is the precise moment to ask which caller, phase, or peer could make a perfectly consistent value false. Structurally: put the context rule in ONE function that every side calls (`validateTerminalInPhase` serves supervisor and coordinator), because two implementations of the same cross-product drift, and prefer refusing to construct the value at all over validating it after the fact.
- (04.5, 2026-07-26) **A fix aimed at one round's finding can reopen an earlier round's finding through a new path.** Twice in four rounds. Arming was moved under the run guard so the cleanup receipt's authority would exist before the CAS that obliges recovery to read it — which reintroduced unbounded work inside a shared lock, the exact defect a previous round had closed. Then a spec pipe was added so the supervisor would stop deriving its command from ambient state — and a supervisor that never reads that pipe blocks the coordinator's write, so a blocked coordinator cannot run the very deadline meant to bound arming. Same mechanism both times: **changing WHEN something happens without re-asking which earlier proofs assumed the old ordering.** The habit that catches it is cheap — when a change moves a step across a boundary (into a lock, later in a lifecycle, onto a new channel), re-read the findings that boundary was created to satisfy, not just the section being edited.
- (04.5, 2026-07-26) **Check whether the repository already solves it before writing the primitive.** The cleanup receipt was published by creating its authoritative name with `O_EXCL` and then writing, syncing and closing — so every failure after the open left that name behind holding readable bytes, and recovery would treat a failed publish as a completion fact. `internal/atomicfile` already had the correct topology, and `atomicfile.ReadInRoot` already refused FIFOs, symlinks and non-regular files with a bounded non-blocking read, which the hand-written reader did not. Both defects were found by the reviewer, in code written next to the working version of itself. The cost is not only the rework: a second, weaker path is now something a future reader can find and copy.
- (04.5, 2026-07-26) **A test fixture that silently fails to reproduce its own scenario is worse than a missing test.** Two teardown tests passed while proving nothing, because the SIGTERM they relied on arrived before the fixture had installed its handler, killing it on the default disposition. Three assumptions were tried before anything was measured: that `trap '' TERM; sleep 30` yields a TERM-immune group (it does not — the shell ignores it, its `sleep` does not, and the shell exits when that child dies), that a shell probe of this was meaningful (it created no real process group, so the signal reached nothing and "SURVIVED" was vacuous), and that a Go helper blocking on `select{}` stays alive (the deadlock detector exits it at once). The fix was a readiness handshake — the same shape as the protocol's own `READY`. Rule: **a fixture that is supposed to be hostile must be proven hostile**, by asserting the precondition it exists to create, and its startup must be synchronised rather than assumed. Green from a fixture that never engaged is indistinguishable from green from a correct implementation.
