# 04.2 — Git transaction (ref CAS + index sync + journal): design pins

Source: CX design ruling, mailbox TURN 186 (DESIGN_REVIEW: REVISE of CC's TURN-186 proposal).

## A — journal placement (AGREE, with conditions)
- Dedicated per-run journal under `RunLock`, named **`CommitTxnDir`/`GitTxnDir`** (NOT `GitDir` — that
  reads as git's real admin dir).
- Part of the AGGREGATE run authority:
  - a nonterminal git transaction is recovered BEFORE any fresh submit authorization / state snapshot;
  - every other run-state/registry mutator must at least FAIL CLOSED on it (or recover it), so no
    standalone mutation can advance the expected state revision and strand a moved ref;
  - a terminal head is durability-confirmed before being trusted;
  - ABSENT is valid ONLY before the run has any accepted git-commit evidence. A vanished journal after
    such evidence is CORRUPTION, not "no transaction".
- Recovery runs WITHOUT re-authorizing the crashed session: registry/session checks authorize
  PREPARE; once the intent is durable, recovery completes the already-authorized intent.

## B — one atomic transaction; IMPLEMENT/FIX acceptance is the final participant (AGREE)
Do NOT run ordinary `transport.Submit` state-CAS and reconcile later. Pre-journal ordering:
1. under the guard, RECOVER any prior git transaction, then normal locked run/journal/registry/turn/
   schema/semantic preparation;
2. durably PUBLISH the canonical artifact;
3. create the authority-neutral snapshot object + freeze the exact pre-identities (INCLUDING the real
   index identity), then a final identity/cancellation recheck;
4. durably PREPARE the journal before the ref can move;
5. drive `ref-cas`, `index-sync`, `state-cas`.
- Crash before PREPARE → only an orphan artifact/object, safe retry. After PREPARE → recoverable;
  recovery never snapshots again.
- The intent holds a BOUNDED, VERSIONED, SERIALIZABLE acceptance plan (NOT the `PreparedTransition`
  closure): exact run/branch/worktree, expected state revision, artifact turn/digest/accepted phase,
  frozen `engine.Decision`-equivalent + source + issued IDs + locked pair-generation fact for the
  VERIFY threshold, `(parent,tree,commit)`, index pre/post identities. Rebuild the state step SOLELY
  from that value. Do NOT put the up-to-1-MiB artifact or the whole RunState into txn's 64-KiB
  payload. Recovery re-reads + re-confirms the exact artifact by KEY; does not re-run semantic
  projection against ambient evidence or mint IDs.
- State participant classification TOTAL: exact expected pre-state = NotApplied; exact accepted turn +
  exact git evidence + exact engine effects + exact issued IDs = Applied; anything else =
  Indeterminate. ConfirmDurable = real artifact + state durability barrier.

## D — explicit real-index CAS (REVISE of CC's `read-tree` proposal)
`read-tree <commit>` directly against the real index is idempotent only if nobody changes the index.
Counterexample (loses user state): snapshot freezes C + observes index I0 → another git stages I1 →
branch CAS moves to C → `read-tree C` overwrites I1 before `status` reports.
- Freeze the exact expected pre-index identity (I0) after the snapshot barrier.
- Build the TARGET index off-to-the-side (`read-tree <commit>` into a temp `GIT_INDEX_FILE`); this is
  NOT the CAS.
- Publish the target index only while HOLDING the standard exclusive index lock, AFTER rechecking the
  live index still has identity I0.
- Enumerate + test every lock/publish crash prefix. NEVER remove/overwrite an UNPROVEN foreign
  `index.lock`. If an owned-lock scheme is used, ownership must survive a crash and be bound to THIS
  txn — path/name/presence is not proof.
- Index `Status` classification (files/index remain untouched on Indeterminate):
  - ref==new, exact expected OLD index (I0), worktree content still == frozen new tree → NotApplied;
  - ref==new, exact TARGET index, exact clean worktree at the frozen commit → Applied;
  - any foreign index identity, post-snapshot worktree identity, wrong symbolic branch/worktree, or a
    mixed combination → Indeterminate.
- Index ConfirmDurable re-proves branch/commit/tree + target real-index identity + clean worktree +
  actual index-file + containing-dir barriers. `status --porcelain=v1 -z --untracked-files=all` may be
  one check, but a bare "status dirty" is not an ownership verdict.
- Ref participant validates strict branch/OIDs AND re-proves the frozen commit is an exact commit with
  `tree==tree` and parent list exactly `[parent]` (branch==new alone is insufficient object evidence).
  Its confirmer is a REAL ref durability barrier, not Observe.

**Index-CAS ownership (CX TURN-187 correction — CONTENT-EQUALITY IS REJECTED).** Content-equality
proves effect-equivalence, NOT ownership: a live foreign git can construct the same index bytes, and
adopting a momentarily-matching `index.lock` it still holds open corrupts the now-live index (POSIX
keeps writing) or races (Windows); content is also not a portable pure-function-of-commit across index
settings/extensions/git-versions/an upgrade between crash and recovery. Use **durable txn-private
target + filesystem same-file identity**:

1. BEFORE journal PREPARE, build the target index at a **txn-id-derived PRIVATE path on the same
   filesystem** as the real index (`read-tree <commit>` into it), fsync it, freeze its digest+path in
   the intent, confirm its directory entry. A pre-PREPARE crash may leave this private orphan (like
   the artifact/object). After PREPARE, recovery validates + uses those EXACT frozen bytes — it does
   NOT rebuild byte-identically.
2. Acquire the standard `<admin>/index.lock` by a **no-replace HARD LINK from the private target**. On
   success the two names are the same file. On `EEXIST`, adopt ONLY if `os.SameFile` / platform file
   identity proves it is the same private-target file-id. Matching BYTES without same-file identity
   are FOREIGN and untouched.
3. Holding the proven-owned standard lock (excludes well-behaved git writers), re-read the live index
   and require its frozen pre-identity (I0). If it differs → remove ONLY the same-file-proven owned
   lock and fail closed; never touch the live index or a foreign lock.
4. Atomically replace `index` with the owned `index.lock`, then file + parent barriers. Crash before
   replace → a same-file-proven owned lock (recover forward); crash after replace → the target is
   live. Keep the private proof through transaction terminality (cleanup = bounded post-terminal
   maintenance).

Hard-link is a reasonable Windows/POSIX primitive (private path + admin index are on one repo
filesystem); FAIL before PREPARE if hard-link is genuinely unavailable (do NOT degrade to
content-as-ownership). Use the repo's rooted/symlink-refusing file primitives + validate regular-file
identities. Freeze the PRE-index identity strongly (a raw digest is conservative + acceptable — a
stat-cache refresh causing a safe fail-closed is fine). Post-index Applied may use the exact frozen
target bytes OR a rigorously-defined semantic index identity + commit-tree/clean checks (must not
mistake stat-cache churn for different staged content). The txn-id binding = the unpredictable
journalled private pathname; same-file identity binds `index.lock` to it across a crash.

## E — RunState schema v6, tuple on the immutable accepted turn
- Add optional typed `AcceptedTurn.GitCommit *GitCommitEvidence{Parent,Tree,Commit}`. REQUIRED exactly
  for acceptances whose authoritative `Phase` is IMPLEMENT_STEP or FIX; FORBIDDEN for all other phases.
- NO mutable "latest commit" duplicate; do NOT overload artifact `EventRef.Digest`.
- Validation: lower-hex 40/64 OIDs of ONE consistent hash width; validate the commit chain in
  receipt-revision order — first git acceptance has parent `BaseCommit`; every later IMPLEMENT/FIX
  acceptance has parent == the preceding git acceptance's commit. Existing entries immutable incl. the
  tuple. Add a ledger/helper projection for the LATEST accepted git evidence (so 04.3/04.5 don't
  reinvent selection).
- Semantic format change → **v6** (explicit migration OR deliberate strict rejection of old v5; never
  silently treat a missing IMPLEMENT/FIX tuple as valid). CC proposes STRICT v5 rejection (greenfield,
  no durable v5 runs in the wild) + move test fixtures/normalizers to v6.
