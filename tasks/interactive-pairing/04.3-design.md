# 04.3 — Immutable review-evidence packet (`internal/evidence`)

Agreed design (CC↔CX mailbox TURNs 212–215, CX AGREE TURN 215). This is the SOLE evidence-packet
authority; a read-only review turn is actionable only through a hash-bound packet materialized from a
COMMITTED Git object, never the live worktree.

## Authority + non-goals
- `internal/evidence` is the only producer/verifier of the review packet. It never mints run
  identity and never mutates run state; its callers (the issuance authorities) bind the resulting
  `EvidenceRef` into the state transition.
- `pull`/`BuildAssignment` stays a read-only, no-mint projection: it re-verifies a state-bound packet
  and projects its `EvidenceRef`, never synthesizes one.

## Source selection (bounded, phase-specific; full identity always bound)
- Every packet binds the complete PROVEN source `{commit, tree}`. Before the first implementation
  acceptance the source is `BaseCommit` (resolve + prove its tree); after, the latest accepted
  `{commit, tree}` (`state.LatestGitCommit`).
- Materialized (verified bytes, never only digests), phase-specific:
  - PLAN_*: frozen task + policy bytes; the task-declared `relevant_repo_paths` read from BaseCommit;
    the materialized candidate-plan / critique context for that turn.
  - CHECKPOINT: the latest accepted implementation step's `parent -> commit` changed blobs +
    deletions; the agreed plan; the accepted implementation report.
  - VERIFY: the cumulative `BaseCommit -> latest accepted commit` review content; task + agreed plan;
    (once 04.5 exists) the coordinator test-evidence record.
- Author-declared selectors (`relevant_repo_paths`) are exact leaf blob paths in the source tree; a
  selector absent from the source fails closed. Discovered diff/changed paths use a lossless Git-path
  representation (may carry non-UTF-8 bytes).

## Bounds (frozen policy: 256 KiB total / 96 KiB file / 8 requests)
- `EvidenceMaxRequests` counts LOGICAL manifest payload entries/selections (files, deletions,
  metadata), NOT unique deduplicated blob files.
- `EvidenceMaxTotalBytes` includes the canonical manifest bytes PLUS every logical retained payload's
  bytes. `EvidenceMaxFileBytes` applies to every retained payload.
- The complete verifier recomputes the identical accounting and fails closed on any disagreement.

## Packet format + publication (immutable-leaf, manifest-last, staging outside inventory)
- A committed packet root `evidence/<turn_id>/` contains ONLY content-addressed regular blob files
  (named by their `<sha256>`) and `manifest.v1.json`. Original Git paths are never recreated on disk
  (no symlinks, case aliases, platform-invalid or non-UTF-8 names).
- `manifest.v1.json` is versioned + canonical; it binds run/turn/phase/source `{commit,tree}`/context
  and maps a lossless Git-path representation + original mode/status -> `{blob sha256, in-packet
  locator}`. `RootDigest` = sha256 of the exact canonical manifest bytes.
- **Publication topology (resolves the atomicfile linked-temp cut):** all `atomicfile` writes (blobs
  and the manifest) happen in an owning per-op STAGING directory OUTSIDE any committed packet root, so
  every `.claudex-tmp-*` and staged file lives in staging. Each finalized staged blob is committed
  into the packet root by a durable no-clobber hard-link `staging/<sha256> -> packet/<sha256>`
  (`os.Link` fails if the target exists) + a rooted parent-directory durability barrier (a thin rooted
  durable-link helper reusing atomicfile's `SyncInRoot`/`syncRootAndDir`). The manifest is linked LAST
  as the commit point. `<sha256>` names carry no repo-derived components — no symlink-traversal
  surface.
- **Recovery + immutability:** staging is freely swept under the run guard (not part of any committed
  inventory). Manifest-ABSENT packet root = recoverable prefix (re-materialize/link missing blobs,
  then link the manifest). Manifest-PRESENT packet root = immutable, verify-only; its inventory must
  equal exactly `{manifest} ∪ {the sha256 blobs the manifest lists}` — any other entry (incl. a stray
  `.claudex-tmp-*`) fails closed. Temps never enter the packet root, so manifest-last recovery and the
  exhaustive verifier are consistent with no committed-alongside-temp removal.
- **Complete verification** (never a spot check): strict schema + canonical-bytes re-encode; expected
  run/turn/phase/source/context; every listed blob re-hashed (type/size/sha256); the bounds
  accounting; and no unlisted consumer-visible payload under the packet root. An existing committed
  manifest is success only if it equals the independently expected root AND the whole packet
  re-verifies; a foreign/mismatched committed packet fails closed.

## State v7 binding (state-owned; one strict meaning)
- State owns the persisted type (no state->transport cycle; transport aliases/projects the wire
  subset onto `EvidenceRef`):
  `AssignmentEvidence{ TurnID, IssuedRevision, ManifestRelPath, RootDigest }`, `RunState.Evidence`.
- Invariants: a live read-only actionable assignment iff an evidence binding exists; binding
  turn/revision == `Assignment.{ID,IssuedRevision}` and path is the derived packet manifest for that
  turn; IMPLEMENT/FIX assignment has none (worktree instead); ownerless/gated/terminal states have
  none; the binding changes only with assignment issuance and is cleared with that assignment.
- The manifest binds run/turn/phase/source/context; the state wrapper supplies the exact
  issued-revision bind at CAS (the final genstore revision isn't safely knowable during off-lock
  construction). Every journal / serializable plan that issues an assignment freezes the expected
  packet root/path and its Applied observation includes that exact binding.

## Integration — publish after locked authorization, before State CAS; fail before PREPARE
Deterministic authoring/bounds/object-selection failures occur during the LOCKED authorized intent
preparation, BEFORE `journal.Run` PREPARE or any earlier participant effect (freeze the verified
recipe/ref in the intent). The four reachable read-only issuance authorities:
- pair attach (PLAN_DRAFT): evidence publish/confirm participant before `state-plan-draft`; expected
  ref frozen in `PairAttachIntent`.
- ordinary submit planning transitions (PLAN_CRITIQUE/PLAN_REVISE/CHECKPOINT-from-planning): publish
  in the authorized locked submit path before State CAS; an orphan before CAS is harmless, identical
  retry re-verifies.
- IMPLEMENT/FIX -> CHECKPOINT: materialize after `SnapshotCommit`, before the commit-txn state bind;
  expected ref/recipe frozen in the serializable `GitAcceptPlan`.
- VERIFY: the replace `verify-activate` journal step publishes/binds before activation. Future
  gate-resume issuers inherit the same obligation.
No new standalone txn; publication composes into the existing pair/git/replace recovery authorities.
